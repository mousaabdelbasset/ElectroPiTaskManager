# Tasks — Functional Documentation

## تحديث الواجهة وقواعد تاريخ الاستحقاق

- نموذج إنشاء المهمة لا يعرض حقل الحالة؛ كل مهمة جديدة تُرسل بالحالة `ToDo`.
- يمكن تغيير الحالة لاحقًا بالسحب بين `ToDo` و`InProgress` و`Done` أو من قائمة الحالة في البطاقة أو نموذج التعديل.
- السحب يغيّر الواجهة فورًا، وإذا فشل `PATCH /api/tasks/{id}/status` تعود المهمة إلى عمودها السابق وتظهر رسالة آمنة.
- لا يوجد ترتيب يدوي داخل الأعمدة لأن عقد الـBackend لا يحتوي على حقل ترتيب.
- لا يمكن إنشاء مهمة بتاريخ قبل اليوم. تعتمد الواجهة على التاريخ المحلي للمستخدم وتطبّق `min` وReactive Forms validator معًا.
- عند تعديل مهمة متأخرة، يبقى تاريخها التاريخي القديم مقبولًا إذا لم يتغير، لكن اختيار تاريخ ماضٍ مختلف يُرفض.
- المهام التي تمر عليها الأيام تصبح متأخرة طبيعيًا؛ القاعدة تمنع اختيار تاريخ ماضٍ جديد ولا تغيّر البيانات الموجودة تلقائيًا.

> هذه القواعد تلغي أي وصف أقدم في هذا الملف كان يسمح باختيار تاريخ ماضٍ عند الإنشاء أو التعديل.

## الغرض

Feature المهام تدير عناصر العمل المرتبطة بمشروع. يمكن إنشاء مهمة، عرضها، تعديل كل بياناتها، تعديل حالتها فقط، حذفها، وفلترة القائمة حسب الحالة.

المهمة تحتوي على:

- `id`: رقم ينشئه السيرفر.
- `title`: عنوان إلزامي، بحد أقصى 200 حرف.
- `description`: وصف اختياري، بحد أقصى 2000 حرف.
- `status`: واحدة من `ToDo` أو `InProgress` أو `Done`.
- `dueDate`: تاريخ استحقاق إلزامي.
- `projectId`: رقم مشروع موجود، وأكبر من صفر.

يُسمح أن يكون `dueDate` في الماضي لأن المهمة قد تكون متأخرة.

## العمليات المتاحة

| العملية          | Endpoint                       | النتيجة الناجحة  |
| ---------------- | ------------------------------ | ---------------- |
| عرض كل المهام    | `GET /api/tasks`               | `200 OK`         |
| فلترة حسب الحالة | `GET /api/tasks?status=ToDo`   | `200 OK`         |
| عرض مهمة         | `GET /api/tasks/{id}`          | `200 OK`         |
| إنشاء مهمة       | `POST /api/tasks`              | `201 Created`    |
| تعديل مهمة كاملة | `PUT /api/tasks/{id}`          | `204 No Content` |
| تعديل الحالة فقط | `PATCH /api/tasks/{id}/status` | `204 No Content` |
| حذف مهمة         | `DELETE /api/tasks/{id}`       | `204 No Content` |

## إنشاء مهمة

```json
{
  "title": "Create home page",
  "description": "Implement the approved design",
  "status": "ToDo",
  "dueDate": "2026-08-01T12:00:00Z",
  "projectId": 1
}
```

لا يوجد `id` في request لأن السيرفر ينشئه.

## تغيير الحالة فقط

```json
{
  "status": "Done"
}
```

القيم الرقمية للحالة غير مقبولة في JSON. استخدم أسماء الحالات النصية. فلتر query يقبل الأسماء فقط وغير حساس لحالة الأحرف.

## قواعد العمل

- العنوان مطلوب ولا يقبل مسافات فقط.
- `projectId` يجب أن يشير إلى مشروع موجود.
- عند نقل مهمة إلى مشروع آخر بواسطة `PUT` يجب أن يكون المشروع الجديد موجودًا.
- حالة غير معرفة تعيد `400 Bad Request`.
- `dueDate` الافتراضي/غير الصالح يعيد `400`، لكن التاريخ الماضي صحيح.
- مهمة أو مشروع غير موجود يعيد `404 Not Found`.
- جميع عمليات القائمة تعيد قائمة فارغة عند عدم وجود نتائج، وليس `404`.
